- [ ] 0-1 遊戲主選單 → **Mods** → 看到 **Steam Engine Expansion v0.1.0**，無紅色錯誤訊息。
- [ ] 0-2 `Mods` 內**沒有**同時安裝 `SteamEngineExpansionMVP`（JSON-only 先行包）；兩者 TemplateName 相同會撞名。

      退出碼 0 = 遊戲啟動、模組列有 SEE、主選單載入無例外（**只證明載入，不證明玩法**）。

## 1. 測試前準備（一次性，5 分鐘）

1. 新開 **Folktails 沙盒**（建議設定：和平模式、`20×` 加速可用；或使用開發者模式解鎖 Power 分類）。
2. 在區內準備：**原木 ≥ 100**、**Plank ≥ 30**、**Gear ≥ 4**、**MetalBlock ≥ 30**、**水**（抽水機或水庫）、**2 名以上搬運工**。

4. 準備至少 1 棟耗電建築（例：伐木廠／磨坊／機械水泵）與傳動軸，能把引擎接到同一機械網路。
5. 命名存檔為 `SEE-P8-BASE`，作為失敗回滾點。

> **不要**在本輪改動任何 `SEE_Config.json` 平衡值（除 §3.1 建議的測試用維護間隔，且測完要改回）。

## 3. 操作附錄：怎麼設定 condition／需求／斷料斷水

### 3.1 設定 condition（v1 無除錯指令）

v1 沒有「直接設定機況」的除錯 UI；採以下任一方式，**測試後請恢復原值**：

| 方式 | 做法 | 時間估算（T2、滿載、20× 速） |
|---|---|---|
| A. 自然磨損（建議） | 讓引擎滿載運轉；磨損率 = `50 / (維護間隔日 × 24)` = `50/(8×24)` = **0.2604／運轉小時**（負載係數 1.0） | 100→30：268.8 遊戲小時 ≈ **11.2 遊戲日** ≈ **4.3 分鐘**；100→0：約 **6.1 分鐘** |
| B. 暫調維護間隔 | 關遊戲 → 改 `Mods\SteamEngineExpansion\SEE_Config.json` 的 `maintenance.intervalDays.T2` 為 `4`（clamp 下限，合法）→ 重開 | 磨損率 0.5208／h：100→30 約 **2.2 分鐘**；100→0 約 **3.1 分鐘** |

- 機況是連續值；容許讀值落在目標區間（例：`Worn` 21–40、`MaintenanceDue` 41–60）。
- 需要精確 30／10 等數字時，可在**備份存檔後**用文字編輯器改存檔（混合形態：世界節點索引＋per-entity 狀態），
  但非必要；以自然磨損到區間即可，並在備註寫下實際讀值。
- `maintenance.enabled=false` 只建議用在「不想被維護打斷」的測試段落，測完改回 `true`。

### 3.2 設定電網需求（滿載／半載／零需求）

| 目標 | 做法 | 判讀 |
|---|---|---|
| 滿載 ≥ 額定 hp | 同一機械網路接足夠耗電建築（或多台）；用「動力」覆蓋層看需求 | 需求 ≥ 460 hp（T2） |
| 半載 ≈ 50% | 只接一半耗電建築，或使用離合器／拆掉部分傳動軸 | 需求約 230 hp；燃料／水耗應約半 |
| 零需求（新預設） | 讓引擎保持接在電網上，等耗電建築停工（入夜或撤走工人／暫停建築）；**不需要**拆傳動軸 | 需求 0 但主狀態 `Running`（待機運轉）：輸出 ≈ 額定 10%（× 機況）、燃料／水按比例、飛輪與煙霧持續（AD-16） |
| 零需求（舊行為） | 把 `SEE_Config.json` 的 `balance.standbyLoadRatio` 設 `0` 並重開遊戲；或讓引擎完全不接電網 | 主狀態 `Idle`、輸出 0、不耗料、不磨損 |

> 原版在供不應求時是「全網一起降效率」；本模組沿用原版，不另做優先序。若需求大於供給，效率 <100% 屬正常。

### 3.3 斷料（燃料）

1. 清空 district 內所有 **Log 與 Plank**（或斷絕通往燃料來源的道路）。
2. 不要接 Conveyor Belts 餵料；等鍋爐內剩餘燃料耗盡（T2 滿載時 3 個 Log 約 27.8 小時耗完，20× 下約 1.4 分鐘）。
3. 主狀態應為 `NoFuel`；補回燃料後 10 秒內恢復。

### 3.4 斷水

| 情境 | 做法 | 注意 |
|---|---|---|
| 有 Timber Pipes | 拆掉接到水艙的管段，或關閉來源 | `auto` 在 v1 解析為 `valve`；若用閥門，關閉 Fill |
| 無 Timber Pipes | 讓搬運工無法補水：隔離水源、清空 district 水庫、或斷開通往水源的路徑 | 斷路可能同時讓維護判 `NoAccessForMaintenance`；記錄即可，不算失敗 |
| 手動排水 | 用 One-way Valve 的 Extract 抽出水艙（有 TP 時） | 注意不要讓水回流 |

> 水艙耗盡後主狀態應為 `NoWater`；若同時缺燃料，`NoFuel` 優先（步驟 4b）。

### 3.5 存讀檔與三模組切換

- 存檔一律用**新檔名**（`SEE-P8-*`），保留 `SEE-P8-BASE` 作為回滾點；不要覆蓋唯一存檔。
- 「退出重進」指**完全關閉遊戲程序**再開，確保存檔節點與 per-entity 狀態都走完整載入路徑。
- 模組切換：Steam 工作坊訂閱／取消訂閱後，在遊戲 Mods 清單啟用／停用，**每次都要重啟遊戲**。
- 移除模組後載入既有存檔（AC-19）：先備份存檔，載入後確認建築存在、`SEE/Error` 0 行、無彈窗。

## 8. 判定規則（避免「看起來正常就過」）

1. **只認證據**：沒有截圖／log／數值記錄的步驟視為未測，不是 PASS。
2. **數值優先序**：狀態文字與面板數值矛盾時，以 `Player.log` 與重跑為準；必要時回報 Lead。
3. **P9 項不阻擋 v1 核心驗收，但阻擋 M5 發佈**：步驟 11／12 的視覺項可標 `N/A（P9 前）`，
   但需求 §19.2 要求 AC-01～AC-21 全綠才能發佈，故 **v1 不能宣告可發佈**。
4. **任何 `SEE/Error` 或紅字例外**：即使功能可用，也先判 FAIL，保留 log 回報。
5. **不可為了讓步驟通過而改平衡值或放寬門禁**；發現問題走新卡或回報 Lead。
